# 对照实验：工具描述的写法

2026-11-27 · 原始记录 `experiments/tool_wording.json` · 重跑 `.venv/bin/python -m tiny_agent.experiment`（约 3 分钟）

## 问题

系统提示词里“怎样描述工具”，对小模型的工具调用影响有多大？

## 设置

**只改一个变量：** 提示词中描述工具的那几行。四种写法（完整文本在 `tiny_agent/experiment.py` 的 `VARIANTS`）：

| 写法 | 内容 |
| --- | --- |
| `examples` | 现有提示词，逐字不变：每个工具给一行完整的 JSON 调用示例 |
| `prose` | 同样的信息改用文字说明（工具名、参数名、用途），不给可照抄的 JSON |
| `schema` | 一份 JSON 格式的工具定义清单（名字、说明、参数类型），外加一行调用格式 |
| `names_only` | 只给两个工具名和调用格式，不说何时用、参数叫什么 |

**固定不变：** 提示词的其余句子、循环代码（`agent.py`，最多 3 步）、工具实现、贪心解码、每次最多 120 个 token。

**任务：** 32 道（`data/valid_cases.json` + `data/test_cases.json`），计算题与笔记题各 16 道。

**模型：** 微调过的 Qwen3-0.6B（适配器是在 `examples` 写法上训练的），以及三个未微调的模型：Qwen3-0.6B、Qwen2.5-0.5B、Gemma-3-270M。

**指标**（都是 32 题中的题数）：

- 首步正确：第一次输出就是正确的工具调用
- 调用成功：整轮里执行过一次正确的工具调用（允许出错后重试）
- 任务成功：调用成功，循环正常结束，并且最终回答用到了工具结果

## 结果

| 模型 | 写法 | 首步正确 | 调用成功 | 任务成功 |
| --- | --- | ---: | ---: | ---: |
| Qwen3 微调 | examples | 32 | 32 | **32** |
| | prose | 0 | 0 | 0 |
| | schema | 0 | 1 | 1 |
| | names_only | 2 | 2 | 1 |
| Qwen3 未微调 | examples | 0 | 2 | 2 |
| | prose | 0 | 0 | 0 |
| | schema | 0 | 8 | **8** |
| | names_only | 0 | 0 | 0 |
| Qwen2.5 未微调 | examples | 22 | 23 | **21** |
| | prose | 1 | 1 | 1 |
| | schema | 31 | 31 | 7 |
| | names_only | 5 | 21 | 20 |
| Gemma-3-270M 未微调 | 四种写法 | 0 | 0 | 0 |

## 发现

**1. 微调模型学会的是那一段提示词，不是工具。**
同一个适配器，在训练用的写法上 32/32，换成信息相同的另外三种写法后最多 1/32。
之前 README 里的“16/16”只在提示词一字不改时成立。

**2. 只看第一步会选错写法。**
Qwen2.5 用 `schema` 时首步正确 31/32，是四种写法里最高的；但任务成功只有 7/32，远低于 `examples` 的 21/32。
原因在第二步：拿到工具结果后，模型不再输出 `{"final": ...}`，而是写一句普通的话，或者把问题复述一遍。
`schema` 写法里没有一条完整的调用示例，模型在“如何结束”这一步失去了可模仿的格式。
也就是说，工具描述的写法不只影响“调不调用”，还影响“怎样停下来”。

**3. 可照抄的示例比文字说明有用得多。**
Qwen2.5 从 `examples` 换到 `prose`：任务成功 21 → 1。两者包含的信息相同，只差有没有一行可以照着写的 JSON。
未微调的 Qwen3 在 `prose` 下 32 题全部把 JSON 包在 Markdown 代码块里，协议一条都没通过。

**4. 报错信息也是工具描述的一部分。**
Qwen2.5 用 `names_only` 时不知道参数名，首步正确只有 5/32，任务成功却有 20/32。
16 道计算题首步全部失败，其中 13 道是参数不对：循环回了一句“calculator 只接受参数 expression”，模型第二步就改对了。
代价是每道题多走一步。提示词里省掉的信息，被报错补了回来。

**5. 结论不能跨模型照搬。**
对 Qwen2.5 最好的写法是 `examples`，对未微调的 Qwen3 却是 `schema`（8 比 2），Gemma-3-270M 在哪种写法下都是 0。
未微调的 Qwen3 在任何写法下首步正确都是 0：`examples` 和 `names_only` 下它直接自己回答，`prose` 下它提出调用但包在代码块里。

## 这些数字的边界

- 32 道题由模板生成，只覆盖一步计算和一次查笔记。差距很大的对比（32 比 0、21 比 1）可信，差几题的对比（如 8 比 2）不要当真。
- 贪心解码下结果是确定的，重跑得到相同数字；这不等于换一批题也相同。
- 四种写法之间除了“形式”还有细小差别（例如句子的先后顺序），没有再拆开。
- “最终回答用到了工具结果”的判定：计算题要求出现正确数字；笔记题要求回答与笔记原文的相似度不低于 0.6。后者是近似判断。
